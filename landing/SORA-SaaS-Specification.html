Complete Feature Specification
Full technical and product brief for building the SORA multi-tenant SaaS platform: Superadmin panel, Clinic admin panel, embeddable widget, automated trial activation, plan-based feature toggles, lead email delivery, and SORA-branded reports.

§1
Product Overview
Architecture

SORA is a multi-tenant B2B SaaS platform. Each IVF clinic is a Tenant. SORA's Superadmin controls all tenants, plans, and feature flags. Clinics manage their own widget, view leads, and access reports from their admin dashboard. Patients interact only with the embeddable widget — no clinic-side login required.

Three-layer architecture
1
SORA Superadmin Panel Private URL
Global control panel for SORA team only. Manage all clinic accounts, activate/suspend plans, toggle individual features per clinic, view aggregate analytics, manage billing, send announcements. Accessible at admin.sorafertility.com/superadmin
2
Clinic Admin Panel Per Tenant
Each clinic gets their own login at app.sorafertility.com/clinic/[clinic-slug]. They see their leads, reports, widget embed code, and account/billing status. Features shown depend on their active plan and superadmin toggles.
3
Embeddable Patient Widget Public
A single JS snippet that clinics paste onto any webpage. Patients complete the 5-min fertility assessment. Results are scored server-side and delivered as a SORA-branded PDF report. Lead details are emailed to the clinic instantly.

Clinic Onboarding — Auto Trial Activation
Zero friction signup
Goal: A clinic submits their details on the B2B landing page and is automatically live on a 14-day free trial — no manual approval from SORA team required. They receive their embed code by email within 60 seconds.
1
Clinic submits registration form Landing Page
Fields: Clinic name, Doctor name, Designation, Clinic city, Phone, Email (becomes login), Password, Website URL. POST to POST /api/clinics/register.
2
Backend auto-creates tenant record
Creates Clinic document with: status: "trial", plan: "trial", trialEndsAt: now + 14 days, widgetToken: uuid(), assessmentLimit: 50. All features default ON for trial period.
3
Welcome email sent automatically Nodemailer / SendGrid
Email contains: Login URL, embed snippet with their unique widget token, 3-step quickstart guide, and link to book a demo call. Sent within 60 seconds of registration.
4
Clinic logs in to their admin panel
They can immediately: view their embed code, customise widget colours, see the live lead dashboard, and access their first reports. No SORA approval step.
5
Superadmin notified of new signup Internal alert
SORA team receives email: clinic name, city, website, plan = trial. Can choose to reach out proactively. All new clinics visible in superadmin dashboard under "New Signups" table.
6
Trial expiry handling
Day 11: Upgrade reminder email sent. Day 14: Widget stops accepting new submissions. Existing leads remain accessible. Clinic sees upgrade prompt in dashboard. Superadmin can extend trial manually.

§7
Assessment Engine (FertiSTAT)
Server-side only
The scoring algorithm runs entirely server-side. It is never exposed in the widget JS or any frontend code. The widget only sends raw inputs and receives a risk band back.

// Trial expiry check — runs daily at 9am IST
cron.schedule('0 9 * * *', async () => {
  const expired = await Clinic.find({
    plan: 'trial',
    trialEndsAt: { $lt: new Date() }
  });
  expired.forEach(c => { c.status = 'expired'; c.save(); });
});

PROMPT 3 — Auth + Clinic registration with auto trial
"Build POST /api/clinics/register. It should: validate inputs with Joi, hash password with bcryptjs, generate a unique widgetToken with uuid(), set plan='trial', status='trial', trialEndsAt = 14 days from now, assessmentLimit=50, default features object (leadEmail:true, pdfReport:true, all others false). Also send an internal notification email to the SORA admin email from .env. Return JWT on success. Also build POST /api/clinics/login returning JWT. Build POST /api/superadmin/login with separate JWT secret."
PROMPT 4 — FertiSTAT scoring engine
"Build a server-side scoring service in /services/fertistat.js. It takes the assessment inputs object and returns: riskBand (low/amber/high), score (0-100), flaggedFactors (array of strings), referralUrgency (immediate/soon/monitor). Scoring logic: assign weighted points across 6 domains — Age/Cycle (age>35 = 15pts, age>38 = 25pts, irregular cycles = 10pts, trying>12mo = 10pts), Medical (PCOS = 12pts, thyroid = 8pts, endometriosis = 15pts, TB = 20pts, diabetes = 8pts), Reproductive (each miscarriage = 8pts, ectopic = 20pts), Lifestyle (BMI<18.5 or >30 = 8pts, smoking = 10pts), Labs (AMH<1 = 20pts, AMH<0.5 = 30pts, FSH>10 = 15pts, AFC<7 = 15pts), Partner (partnerFactorSuspected = 10pts). Auto-elevate to minimum Amber if: ectopicHistory, hasTuberculosis, hasEndometriosis, or miscarriageCount>=2. Map total score: 0-39=low, 40-69=amber, 70+=high. Referral urgency: high=immediate, amber=soon, low=monitor. This file must never be imported in any frontend code."
PROMPT 5 — Assessment endpoint + PDF report + lead email
